# Security policy

## Supported version

Security fixes are applied to the latest commit on `main`. This hackathon project does not currently publish versioned production releases or provide a service-level agreement.

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting feature for this repository when available. If private reporting is unavailable, contact the maintainer through [bryllim.com](https://bryllim.com) and ask for a private security channel.

Do not open a public issue containing:

- API keys, partner secrets, access codes, bearer tokens, or session values;
- real citizen identity, contact, biometric, complaint, or payment data;
- exploit details for an unpatched vulnerability; or
- screenshots or logs that expose private provider responses.

Include the affected route or module, reproduction conditions using synthetic data, expected impact, and a proposed mitigation if you have one. Credentials accidentally committed or shared should be revoked and rotated immediately; deleting the visible file is not sufficient because Git history and logs may retain it.

## Scope note

The repository is a sandbox-oriented hackathon prototype, not an authorized production government system. Reports about official eGov platforms or agency services should be sent to the responsible platform owner rather than this project.
